# AI Engineering Auditor - ground-truth detection benchmark

Generated by `make_report.py` from `results/*.json`; every number below was computed by a script in this directory. Narrative sections were written after reading the computed output.

## 1. Methodology

- Analyzer: `run_analysis(Path(repo), Settings(offline=False))` from ROOT/backend (semgrep + gitleaks + OSV-Scanner + Trivy all status `ok` in every reported run; OSV used live network, sending package names/versions only). ROOT was not modified. Benchmark code was never executed, only read by the analyzer.
- Ground truth: planted issues carry an inline marker `GT:<id>|<category>|<cwe>|<expect>` on the line before the vulnerable line; `SAFE:<id>|<category>` marks look-alikes that must not be flagged. `build_ground_truth.py` extracts them into `ground_truth/<repo>.json` (file, line, category, cwe, expected_detect). Items not detectable by design (prototype pollution, NoSQL injection) are recorded with `expected_detect=false`.
- Match rule (`evaluate.py`): same file, |line diff| <= 3 (<= 1 for unresolved-import), and the finding's rule belongs to the category's rule set (`RULES` in evaluate.py; e.g. any gitleaks finding for a hardcoded-secret). Graph/duplicate/no-tests items ignore line. One finding can satisfy only one planted item.
- Every unmatched finding was labelled by hand in `labels.json` (TP-unplanted / debatable / FP, with reason); a finding firing on a SAFE look-alike is auto-labelled FP. Zero findings remain unlabeled.
- Precision is shown at three levels: strict = planted TP / all findings in that category; adjusted = (planted + true-but-unplanted) / all; and the range with debatable counted as wrong (low) or right (high). Recall = detected / planted-with-expected_detect=true.
- Limitations: all repos are small and synthetic, written by one author (me), one variant per issue type, so recall numbers measure these variants only; 'true-but-unplanted' dependency advisories were not independently verified beyond OSV's output; the real-repo samples are 10 findings each, hand-labelled by me, so they are indicative only.

- vuln_js `.env.local` NEXT_PUBLIC secret: reported by gitleaks as generic-api-key `high`; the semgrep `js-secret-exposed-to-browser` rule matched the code use but not the .env definition.
- Dependency advisories: severity is the max advisory; e.g. transitive certifi and anyio rated `critical`, itsdangerous dev tooling (uv, virtualenv in uv.lock) rated critical/high although they are not runtime dependencies of the library (analyzer has a runtime/dev classifier, but severity still came out high/critical there).

- vuln_py app/main.py:30: semgrep/py-sql-injection-string-build, design/db-select-star

## 10. Notable observations

- Recall on planted security items is high for items matching the shipped rules; failures cluster around JS path traversal via fs reads, express-session cookie flags, DB URL secrets, JS missing-auth when any `.use(...session...)` exists, and tsconfig alias handling.
- Known gaps recorded as expected misses: prototype pollution (2 variants) and NoSQL injection were not detected (0/3), as predicted.
- No JS dependency findings for vuln_js because the repo has package.json but no lockfile (OSV needs lockfiles); not tested with a lockfile. Python requirements.txt was scanned including transitive resolution.
- Secrets: `.env.example` placeholders and hash/UUID constants not flagged (good); DB URL with password missed.
- Not measured: semgrep rules on other frameworks (Django, Node frameworks other than Express), Trivy misconfig on IaC (only Dockerfile findings appeared on the real repo; none planted), runtime of large repos, repeated-run determinism, `kind=subjective` finding quality at scale, anything in TS beyond the planted items, and OSV advisory correctness.
